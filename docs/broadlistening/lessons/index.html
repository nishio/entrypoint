Lessons from Practice

Insights from the development of Kouchou-AI.

Concepts

  • Kouchou-AI is a Tool for Grasping the Overall Structure, Not for Quantitative Analysis — Kouchou-AI (広聴AI) is a tool built on the "structure grasping stance" (構造把握スタンス), not the "quantitative analysis stance" (定量分析スタンス). Its purpose is not to pretend to understand the whole by looking at cluster sizes and frequency distributions (falling into quantitative analysis), but rather to have the user read the overall structure. The single "grasping overall trends use-case" (全体傾向把握ユースケース = rephrased by tokoroten as "finding huge oversights / huge feelings of wrongness") handled by the Web UI is also realized through the structure grasping stance.
  • Broad Listening — Broadlistening — A method of aggregating and clustering large-scale free-text opinions using LLMs to create an "opinion map"
  • Analysis Pipeline (Extraction → Embedding → Hierarchical Clustering → Labeling → Visualization) — Analysis pipeline — extraction → embedding → hierarchical clustering → labeling → visualization

Extraction

  • Opinion Extraction Faithfulness: Retesting with Public Models and Prompt Improvement — In the opinion extraction stage of Kouchou-AI (広聴AI), the meaning of the original text can be rewritten even if the processing completes successfully. We compared 31B, 27B, and 2B public models on the same footing using a Japanese challenge set and public data. The reversal of sarcasm polarity occurs even in 27B and 31B, and possibilities and suggestions are strengthened to "should" due to the influence of the input/output examples in the default prompt. With an extraction prompt that adds rules and a single line "confirm the true intention first", rewrites in the unused test set are reduced to 0 cases for 31B and 2 cases for 27B, but the output leans towards being a direct copy of the original text. Small models fail to perform extraction without JSON grammar constraints.
  • "Semantic Rewriting" Occurring in Opinion Extraction by Small Local LLMs — When extracting Japanese opinions from short texts in other languages using a small local LLM (Qwen3 4B), the processing completed, but issues occurred such as reversing the subject of the claim, fabricating non-existent relationships, paraphrasing emotional expressions, and dropping requests. Completion of the run should not be considered a success; adoption should only occur after verifying against the original text.

Labeling

  • Labels are Summaries, not Tables of Contents — Human Judgment in Label Design — Human judgment on label design: Labels should be organized as "summaries" rather than "tables of contents," covering up to the top 2-3 axes. However, the evaluation criteria depend on the use case, and the desirable behavior of sampling, rep args, and judge changes between grasping the overall trend and discovering a small number of important issues. One of the root causes for dimensions dropping out of labels is that the upstream labeling input is a random sampling of up to 30 items via API and 10 items in CLI/default.
  • Break Down Label Quality Judgment into Binary Criteria and Weights, Not 1 to 5 Points — It is better to decompose the judge of cluster label quality into a rubric evaluation of binary criteria + weights + fatal penalty, rather than an abstract 1-5 point scale. First, it should be calibrated against human judgment using the existing judge bundle of [8,40], and run as an experimental artifact instead of putting it into the standard pipeline.
  • Do Not Critique Label Quality in Isolation; Have Users Choose via Blind A/B Testing — In label quality experiments, rather than having humans critique single labels, multiple label candidates generated from the same tree/evidence are compared in a blind A/B test that hides algorithm origins. The difficult full UI evaluation is decomposed into single labels, adjacent label sets, and labels with representative examples, and their pairwise preferences are used as judge calibration data.
  • A/B Experiment on Top-Level Label Refinement and Misinterpretation of Length Direction — As a result of running 7 items of human preference A/B (none vs setwise_refine) on the 2026-06-02 LLM grouping 400-item corpus with label_only, setwise_refine was the winner in 7/7 cases. Initially, this result was organized as a verbosity confound, but a reinvestigation on 6/8 and 6/9 revealed that I had conversely misidentified "which one is more verbose". In fact, refine_none (= no top-level refinement = merge_labels as is) is verbose, and refine_setwise (sibling-aware refinement) is shorter. Therefore, the v1 result captured "refinement on > refinement off", and the exact structure is that the verbosity reduction effect and the sibling-awareness effect are mixed within the refinement. The templating issue of the MERGE_LABELLING_PROMPT few-shot remains valid.

Clustering and Visualization

  • First Experiment of LLM Grouping — How Well the Appearance of Scatter Plots Holds Up — For the first experiment of LLM grouping, it is good to run analysis_mode=llm_grouping with 400 lines of Japanese comments and observe to what extent the scatter-compatible appearance holds up.
  • Fixing Seeds for UMAP / k-means Was Not a Mechanism for Reproducibility — Fixing the seed for UMAP / k-means was not born as a 'mechanism to achieve perfect reproducibility,' but rather from a 'desire to minimize visual fluctuations as much as possible,' and was later reevaluated as a trade-off with parallelism.
  • Drawing an Opinion Map as a Graph: Intra-Cluster Minimum Spanning Trees and Inter-Cluster Bridges — A proposal to break away from the design of burdening UMAP 2D with both semantic clustering and visualization quality, and instead visualize as a graph drawing using intra-cluster MST + mutual kNN, inter-cluster bridge edge, and 2-stage cluster-separated layout. This can be an answer from the visualization side to the existing niizuma critique.
  • The Issue with Default Cluster Counts Was a Discrepancy Between Documentation and Implementation, Not the Algorithm — The essence of the cluster count default issue is not about "algorithm selection" but rather "the discrepancy in AI usage paths between docs, implementation, and interfaces," and PR #832 is a fix that narrows this gap.

Public UI and Scope

  • What Is Required of a Public UI for Broad Listening Results Is Not "Whether It Is a Scatter Plot" — The requirements for the public UI of broadlistening results are not "whether it is a scatter plot", but the volume, perspectives, issues, traceability to individual opinions, avoidance of burying minority opinions, elimination of arbitrariness, and visualization of the next questions. Derived from ohki-shingo's organization.
  • The Scope of Kouchou-AI is Up to the Discovery of Key Insights — Lineage of the Scope Line — The lineage of the scope line: "The scope of Kouchou-AI (広聴AI) is up to the discovery of key insights, and beyond that is the accompanying partner". Starting from the 2025-07-16 marketing strategy mtg, it has been consistent through the 2025-11-29 Ken Suzuki blog and the 2025-12-06 direction meeting up to the current plugin policy.

Peripheral Topics

  • Connecting Kouchou-AI to the KJ Method's Public Hypothesis Generation — A teleology connecting Kouchou-AI (広聴AI) to the public hypothesis formation of the KJ Method (KJ法). It separates unverified hypotheses and product design principles without assuming the quality improvement of the KJ Method prompt has been verified.
  • Whether to Add Pipeline Steps Should Be Decided by the Responsibilities of New Artifacts — The proposal to add pipeline steps, which repeatedly appeared in recent research, should be judged not by the number of steps but by whether 'new artifact responsibilities should be made first-class'. Boundary cases, counterexamples, and bridges should be independent artifacts, while mere label copy improvements should be kept as experimental optional steps.
  • Broad Listening Tool Catalog (Draft) — A tool catalog draft to explain Kouchou-AI (広聴AI) / Idobata (いどばた) / Cartographer / Jigsaw Sensemaker / tttc-light-js to the outside world without confusion. It will be repurposed for the #564 public case page and the August 2nd tech/tool materials.
  • Insights from the Book 'Broad Listening That Changed Elections' for Development Decisions — Extracts insights from the book that influence future development decisions. Separates design intentions, empirical values, and verification results, treating the improvement of labeling quality with the KJ method prompt as an unverified hypothesis.
