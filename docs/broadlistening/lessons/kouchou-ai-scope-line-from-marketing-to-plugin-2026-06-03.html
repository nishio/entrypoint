Kouchou-AI Scope Line From Marketing To Plugin 2026-06-03

Translated from the Japanese original: wiki/analyses/kouchou-ai-scope-line-from-marketing-to-plugin-2026-06-03.md (commit 3459fc6). Machine-translated by Gemini and not yet reviewed by NISHIO Hirokazu.

Summary: The lineage of the scope line: "The scope of Kouchou-AI (広聴AI) is up to the discovery of key insights, and beyond that is the accompanying partner". Starting from the 2025-07-16 marketing strategy mtg, it has been consistent through the 2025-11-29 Ken Suzuki blog and the 2025-12-06 direction meeting up to the current plugin policy.

Argument

"The scope of Kouchou-AI (product) is up to the discovery of key insights, and beyond that (policy reflection, citizen satisfaction improvement) is the job of the accompanying partner." This scope demarcation is a premise of the strategy currently articulated in plugin-system and broadlistening-tool-ecosystem-vision, but this line itself was already clearly stated in the 2025-07 marketing strategy mtg. It has been consistent over nearly a year, and the subsequent blog, direction discussions, and plugin design can be read as representing this line from different angles.

Timeline

2025-07-16: Marketing strategy mtg (marketing-strategy-mtg-2025-07-16)

  • A one-off meeting of board-level members. The oldest clear statement of the kouchou-ai scope line currently confirmable on the wiki.
  • Main arguments:
    • If policy reflection is to be included in the scope, not only tools but also accompanying support and consulting-like actions are necessary.
    • However, accompanying support is not within the scope of OSS development.
    • Therefore, a line is drawn: "The tool called Kouchou-AI handles up to the discovery of key insights, and beyond that we create success cases together with deployment partners."
    • The division of roles between Polis (developed by Colin) and policy making (Audrey Tang's team) is cited as a reference model.
  • Alongside this scope line, policies such as product improvement persona ≠ marketing persona, local government stakeholders are divided into the mayor / broad-listening department representative / engineers, and (P0) SaaS conversion (can be tried by registering an API key) were already in place.

2025-11-29: Ken Suzuki blog (kensuzuki-broad-listening-insight-types-2025-11-29)

  • Rather than treating "broad-listening" as a single method, it was organized that different tools are used for different types of desired insights.
  • Divided by use case: scatter plot / cluster overview type (TTTC / Kouchou-AI) for agenda discovery, Polis for uncommon ground, AI interview for deep policy exploration.
  • This can be read as a paraphrase of "Kouchou-AI = up to key insight discovery" from 2025-07. It was the first time that the "outside the scope of Kouchou-AI" was documented as being filled by other use-case-specific tools (Polis / AI interview).

2025-12-06: About the direction of Kouchou-AI (kouchou-ai-direction-2025-12-06)

  • The first direction discussion following the Ken Suzuki blog.
  • Arguments:
    • Need to separate analysis modes by use case.
    • A GUI node editor is too heavy; customization is more realistic with JSON / YAML-like config.
    • Do not rewrite everything before the book publication; cut a stable release and proceed with next-generation experiments on a separate track.
  • The idea that "kouchou-ai itself takes on the key insight discovery mode, and other uses run in parallel via other modes/implementations" leads from here to the v4 stabilization and v5 large-scale refactor in versioning-strategy.

Present (2026-05 - 06): plugin-system and broadlistening-tool-ecosystem-vision

  • plugin-system: A design that makes input/analysis/visualization replaceable as plugins. docs/development/why-plugin-system.md writes the reason for adoption as "A breakthrough for the dilemma of wanting to maintain compatibility vs wanting to experiment with new features. It separates concerns at technical boundaries, enabling parallel evolution without requiring consensus."
  • broadlistening-tool-ecosystem-vision: A two-tier ecosystem that narrows the Web UI down to a simple default mode, loads various experiments onto the CLI, and shares them within the community.
  • At this point, the outward scope line from 2025-07 of "Tool = up to key insight discovery / Accompanying = partner" is nested with the inward structural division of "Web UI = huge incongruity discovery / CLI = analyst experiments / Community = place for sharing".

What has been consistent

  • The intention of not selling Kouchou-AI as an omnipotent tool has been consistent from 2025-07 to the present.
  • The purpose of cutting the scope was originally on the marketing side ("What should be targeted to create a success case?"), and later aligned with technical circumstances (pluginization / compatibility / parallel evolution).
  • The positioning of partners was also mentioned with specific names (Code for Japan / Polipoli / Polis role division) as of 2025-07, which leads from there to the current dd2030 ecosystem (idobata (いどばた) / polimoney / decidim integration).

What has changed

  • In 2025-07, the premise of the discussion was the current recognition that "the engine quality of Kouchou-AI has not reached a practical level (Ken Suzuki's personal opinion)". Specifically, category merging, category errors, noise, and weakness in key insight discovery were mentioned. This was posed as the (P1) Engine Quality issue, and subsequently became the root of label quality-related work in 2026-Q2, such as label-coverage-policy-2026-05-29 / label-refinement-input-scope-2026-05-29 / the refactoring of hierarchical labeling.
  • In 2025-07, "(P2) UI / visualization improvement is low priority", but in 2026, UI-related discussion points have come to the fore, such as public-ui-requirements-for-broadlistening / ohki-discussion-reflection-2026-05-25 / chart-scroll-ux-decision. This can be organized as a shift in focus to the problem of how to hand the discovery to the reader while maintaining the "key insight discovery" scope.
  • The personas in 2025-07 were three tiers: "local government representative / mayor / frontline". broadlistening-tool-ecosystem-vision in 2026 has three figures: "general user / in-house demo role / analyst, researcher", and the bridge role (close to the "broad-listening department representative / frontline" in 2025-07) is clearly stated as an independent figure. This 'in-house demo role' was an implicit layer in 2025-07.

Why leave this lineage summary

  • When ongoing discussions (plugin / Web UI simplification / CLI expansion / community) are seen not as a new paradigm shift, but as a result of representing the 2025-07 line from the technical side, the fluctuation in design decisions is reduced.
  • For example, when a discussion comes up about whether to "add advanced options to the Web UI", if we know that "the scope of Kouchou-AI is up to key insight discovery" from 2025-07 and the Web UI simplification decision of broadlistening-tool-ecosystem-vision are on the same line, the choice is less likely to waver.
  • At the same time, the separation that the "(P1) Engine Quality" issue (category merging, error, noise) of 2025-07 is a remaining issue to be solved independently of the scope line becomes clear. Even if the scope is reduced, the quality issue does not disappear.

Open Questions

  • The current status of candidate partners (Code for Japan / Polipoli / decidim integration) brought up in 2025-07 needs separate inventorying. Where is the decidim integration, which was estimated to be on a 3-year span, right now?
  • "(P0) SaaS conversion (can be tried by registering an API key)" is recorded as PR submitted and awaiting review as of 2025-07. How that connects to the current Azure demo environment / SaaS conversion discussion needs to be organized separately in the context of deployment / Azure demo environment (Google Drive management).
  • How far has the improvement work on the quality of key insight discovery (category merging, error, noise) progressed now? How has Ken Suzuki's assessment that it "has not reached a practical level" from 2025-07 changed after the label quality-related work in 2026-Q2? — This can be reconfirmed at the stage where the evaluation results of clustering-labeling-comparison-corpus-2026-06-02 and human-pairwise-label-preference-experiment-2026-06-02 are gathered.
